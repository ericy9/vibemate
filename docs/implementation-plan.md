# VibeMate 实施计划

## 1. 交付策略

开发顺序从 Agent 边界逐步走向用户界面。每个阶段都必须产出可以独立测试的结果，
不能依赖尚未实现的桌宠渲染器来验证核心逻辑。

## 2. 第零阶段：调研与协议设计

### 目标

- 确认参考代码和素材的许可证。
- 记录 Codex 与 Copilot 的 Hook 数据结构和超时行为。
- 确定第一版运行时技术和仓库结构。
- 定义协议 v1、统一状态、会话键和权限结果。

### 交付物

- 协议类型或 Schema 及示例
- 两个 Agent 的事件映射表
- 权限失败回退约定
- 数据清理和载荷大小限制
- 使用合成、非敏感 Hook 数据制作的测试 Fixture

### 退出条件

两个 Agent Adapter 都能基于明确记录的输入进行设计，并且核心会话存储不依赖
任何 Agent 特有的字段名称。

## 3. 第一阶段：编码端事件采集

### 3.1 核心接收服务

- 只监听 loopback 地址，并动态选择可用端口。
- 持久化运行时端口信息，供已安装的 Hook 发现服务。
- 校验协议版本、Agent、会话身份、事件大小和字段。
- Agent 特有的解析逻辑不能进入共享会话存储。

### 3.2 共享会话存储

- 使用类似 `<source-profile>|<agent>|<session-id>` 的内部会话键。
- 保存当前统一状态和有长度上限的最近事件列表。
- 实现确定性的状态转换和完成事件去重。
- 为开发观察器和未来 UI 提供只读快照 API。

### 3.3 权限 Broker

- 为每个待处理请求生成唯一请求 ID。
- 将等待中的响应绑定到 Agent 和会话身份。
- 实现“第一个有效最终决定生效”的规则。
- 请求过期、服务关闭或归属不明确时返回“无决定”。
- 不能通过普通状态事件推断权限处理资格。

### 3.4 Codex Adapter

- 安装和卸载时只修改 VibeMate 自己拥有的官方 Hook 条目。
- 把生命周期事件映射到协议 v1。
- 完成官方权限请求的双向闭环。
- 第一小步先不加入 JSONL 轮询；只有官方 Hook 出现明确且可复现的事件缺口时，
  才评估 fallback monitor。

### 3.5 Copilot Adapter

- 优先读取 `COPILOT_HOME`，为空时回退到 Copilot 标准目录。
- 增量合并 VibeMate 自己拥有的 Hook，不覆盖用户文件或用户 Hook。
- 把 camelCase 生命周期事件映射到协议 v1。
- 完成权限请求的双向闭环。
- 如果权限事件已经由用户的其他 Hook 接管，必须保留原 Hook，并明确报告
  VibeMate 权限处理未安装。

### 3.6 开发观察器

- 实时显示会话快照和最近事件。
- 显示经过清理的待处理权限详情。
- 为集成测试提供明确的 Allow 和 Deny 控件。
- 展示拒收事件、超时、无决定和去重等诊断信息。

### 3.7 验证

- 为 Schema、映射、状态转换、数据清理和去重编写单元测试。
- 为 Hook 标准输出和失败回退行为编写契约测试。
- 使用多个并发合成会话进行集成测试。
- 使用真实 Codex CLI 验证权限请求。
- 使用真实 Copilot CLI 验证权限请求。

必须进行真实 Agent 测试。手写 HTTP 请求无法证明 Hook 的标准输入、标准输出和
阻塞行为与实际安装的 CLI 版本一致。

## 4. 第二阶段：桌面应用和桌宠

- 加入 Electron 主进程和托盘生命周期。
- 桌面层只消费核心快照 API 和权限 Broker API。
- 实现透明且尽量不抢焦点的桌宠窗口。
- 实现权限气泡，显示 Agent、项目、工具和经过清理的操作详情。
- 增加完成、失败、等待交互的系统通知和声音。
- 桌面 UI 隐藏或不可用时，仍需保留 Agent 原生权限回退。

## 5. 第三阶段：会话导航

- 增加紧凑 HUD 和完整 Dashboard。
- 追踪未读完成事件和待处理交互。
- 在平台 API 可靠的情况下采集终端进程信息。
- 尽力切换到对应终端，但终端焦点信息不能作为权限路由的身份依据。

## 6. 第四阶段：WSL2 与 Remote SSH

- 将每个远端连接视为独立的来源配置。
- 使用带身份绑定的安全传输，不能直接把本地接收服务暴露到局域网。
- 向受支持的 Linux 主机部署版本匹配的 Hook。
- 修改远端配置前，先验证 Node.js 和目标 Agent 是否存在。
- 实现连接健康、重连、升级和清理流程。
- 分别验证 Codex/Copilot 对树莓派 CPU 架构的支持；VibeMate 的 Node Hook 可以
  运行，不代表 Agent CLI 本身一定支持该架构。

## 7. 第五阶段：个人桌面伙伴功能

- 引入独立于 Agent 会话的提醒调度器。
- 增加喝水、久坐、休息和专注提醒。
- 复用桌宠、声音和系统通知等展示通道。
- 提醒模块的状态和持久化必须与编码 Agent 状态分离。

## 8. 建议的仓库边界

具体语言和工具链留到第零阶段决定。预期模块职责如下：

```text
packages/
  protocol/          共享事件和权限协议
  core/              会话存储、状态转换、权限 Broker
  adapter-codex/     Codex Hook Adapter 和安装器
  adapter-copilot/   Copilot Hook Adapter 和安装器
  observer/          开发用事件与权限观察器
  desktop/           后续的 Electron、桌宠、气泡和通知
```

Adapter 可以依赖协议层，但协议层和核心层不能导入 Agent Adapter 或 Electron。
个人提醒最终也应作为独立模块，由桌面展示层消费。
